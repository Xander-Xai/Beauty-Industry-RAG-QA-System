# 化妆品行业多模态RAG问答助手改造架构

## 二、知识库层：多模态知识存储与检索优化
| 模块                | 具体内容（化妆品适配）                                                                 | 技术实现                          | 与原汽车项目差异点                     |
|---------------------|--------------------------------------------------------------------------------------|-----------------------------------|----------------------------------------|
| 1. 存储架构         | - **向量数据库**：<br>  ▶ 存储文本向量（产品/原料/法规文本经模型编码）<br>  ▶ 存储图像向量（产品图/原料图经BLIP编码）<br>  ▶ 选型：保留原项目FAISS（轻量化），生产环境可替换为Milvus（支持动态扩容）<br>- **源数据存储**：<br>  ▶ 原始文件：OSS/AWS S3（存储图像、PDF文档）<br>  ▶ 结构化数据：PostgreSQL（存储文本原文、图像标签、权限信息） | FAISS（向量）+ PostgreSQL（元数据）+ OSS（文件） | 新增“权限标签字段”（如“研发部可见”“销售部可见”），限制敏感数据访问 |
| 2. 向量生成与索引   | - **向量生成模型**：<br>  ▶ 文本向量：保留原项目`all-MiniLM-L6-v2`（轻量化），新增`BGE-M3`（中文优化，提升成分术语检索精度）<br>  ▶ 图像向量：沿用原项目BLIP模型（生成图像描述并编码）<br>- **索引构建**：<br>  ▶ 文本索引：HNSW（支持高频查询，如销售查产品）<br>  ▶ 图像索引：IVF_FLAT（提升原料图匹配精度）<br>  ▶ 双阶段检索：保留原项目“bi-encoder（召回）+ cross-encoder（排序）”逻辑 | 模型调用：transformers库<br>索引构建：FAISS API | 新增`BGE-M3`模型支持中文化妆品术语，优化索引类型适配行业查询场景 |
| 3. 知识库更新机制   | - **增量更新**：新增产品/原料数据时，自动生成向量并插入FAISS，不重建全量索引<br>- **定期更新**：每周日凌晨更新法规库（同步药监局最新公告）<br>- **过期清理**：每月删除3年前的过期产品数据（如已停产产品） | 定时任务：Celery + Redis          | 新增法规库自动同步逻辑，替换汽车项目的车型数据更新机制 |

## 五、核心改造清单（给AI编程工具的关键指令）
1. **数据替换**：删除汽车领域数据集，导入化妆品文本/图像/文档数据，建立“产品-原料-法规”关联关系；  
2. **模型微调**：用化妆品问答数据微调`chatglm3-6b`和BERT意图识别模型，重点优化成分、法规类问题；  
3. **检索适配**：新增`BGE-M3`文本向量模型，调整检索规则以优先匹配“成分术语”“法规条款”；  
4. **权限控制**：在知识库和检索层添加部门权限标签，实现数据隔离；  
5. **输出优化**：改造输出模板，增加“法规来源标注”“成分安全性提示”等化妆品特色字段。

```mindmap
## 化妆品多模态RAG问答助手
### 数据层
- 数据源：产品/原料/法规文本、产品/原料图像、研发/质检文档
- 预处理：文本标准化（行业术语）、图像标注、文档结构化

- 存储：FAISS向量库 + PostgreSQL元数据 + OSS文件

- 输入：文本/图像/混合输入，意图识别（产品/原料/法规）
- 检索：双阶段检索（bi-encoder+cross-encoder）+ 权限过滤
- LLM生成：chatglm3-6b（化妆品微调）+ 角色化提示词
- 输出：文本结论+依据+关联图像
### 部署层
- 容器化：Docker+K8s（服务拆分）
- 监控：检索延迟/准确率监控 + 告警
- 安全：OA登录 + 部门权限控制
```
